- **Названия мест:** «Русское (Latin, 中文)», например «Чэнду (Chengdu, 成都)».
- **Свои файлы:** `app/tour-*.tsx` (страница в режиме программы тура), `app/page.tsx` (старый планировщик; включается, если в плане появятся дни), `data/tour.json`, `data/tour-places.json`, `data/place-guides.json` (путеводители, проверка `scripts/check-place-guides.mjs`), `lib/tour-route.ts`, `lib/transports.json`.
- **Статус рейсов:** workflow `transport-status.yml` каждые 10 минут до 4 ноября 2026 собирает `transport-status.json` и публикует его командой `publish transport-status.json` (меняется только этот файл в текущем выпуске).
- **Фото розеток** не хранятся в Git: их скачивает `npm run assets` (`scripts/fetch-assets.sh`).
- **Закрытые данные:** `prices`, `questions`, `packing`, `flightCost`, `tourPayment` из `data/tour.json` отдаёт сервис аккаунтов из своей копии. После изменения выполните `deploy/update-private-tour-from-mac.sh` (нужен root-доступ к серверу) — он обновит только `tour.json` и перезапустит `china-account`.

## Стандарт сайтов путешествий · версия 1.1 (23.10.2026)

Сайты поездок семьи — `<поездка><год>.proskurnin.com` — делаются **одним способом**: один стек, одна структура, один сервис аккаунтов, один CI и деплой. Это касается и будущих поездок, и сайтов о прошедших. Агент, который работает с любым из этих репозиториев, следует этому разделу; отступить можно только с согласия владельца, записав причину в раздел «Этот сайт».

Эталон для нового сайта — репозиторий **turkey2027.proskurnin.com**. Китай и Европа построены по стандарту, но в них остался старый «планировщик» маршрута (`app/page.tsx` с импортом плана) — в новые сайты его не переносим.

### Принципы
1. **Одинаковое — одинаково.** Общие файлы (список ниже) побайтно совпадают во всех репозиториях. Это проверяет `npm run check` (`scripts/check-standard.mjs` сверяет их с `travel-standard.json`).
2. **Своё — в отведённых местах.** Особенности сайта живут только в файлах сайта: `lib/site.ts`, `server/account/site.mjs`, `server/account/public-plan.mjs`, `data/*`, страницы, тема, `lib/tour-route.ts`, скрипты в `package.json`.
3. **Одна структура разделов.** Набор и порядок вкладок одинаковые; лишнее скрываем, а не переименовываем.
4. **Публичное и личное разделены.** Публичное (маршрут, программа, полезная информация) видят все. Наше (вещи, деньги, заметки, журнал) — только после входа, хранится на сервере в аккаунте, не в браузере и не в публичной сборке.
5. **Своя база у каждого сайта.** Аккаунты и личные данные сайтов не смешиваются.
6. **Выкладка только через CI.** Слияние в `main` = выкладка. Никаких ручных копирований на сервер, root-доступа из CI, правок «на живом».
7. **Безопасный деплой.** Проверка после выкладки, автоматический откат, 10 последних выпусков.
8. **Без секретов в Git.** Ключи, `maps-config.json`, базы, `.env` — только в секретах GitHub и на сервере.
9. **Своё оформление у каждой поездки.** Цвета, шрифты, иллюстрации — свои (Китай: киноварь и нефрит; Турция: море и паруса). Структура и поведение — общие.
10. **Проверено — значит проверено.** Факты со ссылкой на источник и датой; непроверенное помечено как предварительное. После выкладки сайт проверяют глазами: ПК и телефон 390 px.

### Стек
- Node **22.22.2** (`.nvmrc`), npm, `package-lock.json` обязателен.
- React 19 + TypeScript, **vinext** со статическим экспортом (`next.config.ts`: `output:'export'`) → `dist/client`, его отдаёт Apache. Серверного рендеринга нет.
- Tailwind 4 + `components/ui` (shadcn / Base UI), иконки `lucide-react`.
- Карты: `@googlemaps/js-api-loader`, `@googlemaps/markerclusterer`, `leaflet` — из npm, не с CDN.
- Версии зависимостей одинаковые во всех сайтах; обновляем во всех сразу.

### Авторизация
- Сервис `server/account`: Node 22, встроенные `http`, `crypto`, `node:sqlite`, без зависимостей. Контейнер `node:22-bullseye-slim`, пользователь 1000, read-only, без capabilities, порт только на 127.0.0.1.
- Роли: **владелец** (один, управляет людьми), **участник** (закрытые разделы), **зритель** (только публичное). Вход только по приглашению владельца со страницы `/account/`, ссылка действует 24 часа. Публичной регистрации нет.
- Пароль от 12 символов (scrypt), сессия 7 дней, cookie `__Host-<site.id>-session` (Secure, HttpOnly, SameSite=Lax), лимиты попыток, проверка Origin.
- API: `/api/account/*` — вход и пользователи; `/api/trip/tour` — закрытые поля `data/tour.json` (если файла нет — пустые); `/api/trip/storage` — личные данные пользователя (`personal`, `preferences`, `packing`, …; новый ключ — с проверкой формата и тестом); `/api/trip/plan`, `/api/trip/state`.
- Первый вход владельца / восстановление: `docker exec <место>-account node /app/owner-invite.mjs <email>` на сервере.

### Карты
- Основная — **Google Maps** (Maps JavaScript API, AdvancedMarker), запасная — **OpenStreetMap** (Leaflet). Переключатель на карте, выбор запоминается; если Google не загрузилась — предлагаем OpenStreetMap.
- Ключ — секрет **`GOOGLE_MAPS_KEY`** (один на все сайты), CI пишет его в `public/maps-config.json` перед сборкой. В Google Cloud Console ключ ограничен по HTTP referrer и по API (Maps JavaScript, Routes) — **новый домен добавить в ограничения ключа**.
- Map ID — переменная **`GOOGLE_MAPS_MAP_ID`**; пока её нет — тестовый `DEMO_MAP_ID`.
- Линии переходов на карте — схема, не реальные треки; так и подписываем.

### Данные
- `data/tour.json` — исходник поездки. Закрытые поля `prices`, `questions`, `packing`, `flightCost`, `tourPayment` убирает `scripts/export-public-tour.mjs`; участникам их отдаёт сервис аккаунтов из своей копии.
- Сгенерированные файлы (`data/public-tour.json`, `data/public-plan.json`) руками не правим — правим исходник.
- Закрытая копия `plan.json` / `tour.json` лежит у сервиса (`/opt/<место>-account/releases/…`); CI её не перезаписывает. Изменили закрытые поля — обновите копию на сервере и перезапустите сервис.
- Публичный репозиторий не содержит закрытого; если поездка личная — репозиторий приватный.
- Названия мест: «Русское (Latin, местное письмо)», например «Чэнду (Chengdu, 成都)».

### CI и деплой
- Один workflow `.github/workflows/deploy.yml`: pull request — проверки и сборка; push в `main` — ещё и деплой.
- Контракт `package.json`: `npm run assets` (необязательно), `npm run check` (начинается с `node scripts/check-standard.mjs`, дальше тесты аккаунтов, TypeScript, проверки сайта), `npm run build` → `dist/client` с `index.html` и `account/index.html`.
- CI отправляет архив (`site/` + `account/`) пользователю `<место><год>-deploy@80.87.199.223`; его ключ может выполнить **только** `deploy <sha> <run>` или `publish <файл.json>` (forced command `travel-site-ci-entry`).
- Сервер (`travel-site-deploy`): распаковка, перенос разрешённых файлов, обновление кода сервиса аккаунтов при изменениях (копия базы, проверка, откат), атомарное переключение, проверка `release.txt` и `/api/account/me` по HTTPS, откат при ошибке, хранение 10 выпусков. Журнал `/var/log/travel-site-deploy.log`; ручной откат — `travel-site-deploy <место><год> rollback`.
- Секреты: `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`, `GOOGLE_MAPS_KEY`; переменные: `GOOGLE_MAPS_MAP_ID`, `DEPLOY_HOST` (необязательно).
- Исходники серверных скриптов: `~/serverops-backups/travel-sites/` на сервере управления (ops-us-40.160.252.24).

### Новый сайт поездки
1. Репозиторий `<место><год>.proskurnin.com` (приватный, если поездка личная). Скопировать turkey2027 без `.git`; поменять `lib/site.ts`, `server/account/site.mjs` (порт из реестра), `data/*`, страницы и тему; убрать содержимое Турции; раздел «Этот сайт» в `AGENTS.md`, `README.md`; добавить строку в реестр сайтов **во всех репозиториях** (это изменение стандарта, см. ниже).
2. DNS A → 80.87.199.223; vhost Apache и сертификат Let's Encrypt по образцу Турции (заголовки безопасности, кеш `/_next/static/`); домен — в ограничения ключа Google.
3. Сервер: пользователь `<место><год>-deploy` без sudo, ключ с `command="/usr/local/libexec/travel-site-ci-entry <место><год>",restrict`, строка в `/etc/sudoers.d/travel-sites`, `/etc/travel-sites/<место><год>.conf`.
4. Сервис аккаунтов: `travel-site-account-install <место><год> <email владельца> < bundle` (код аккаунтов + `data/plan.json` + `data/tour.json`); ссылка владельцу — из `/root/<место><год>-owner-invite.txt`, после активации файл удалить.
5. База — в ночной бэкап (`fleet-backup.py`); секреты в репозиторий; первый PR → зелёные проверки → слияние → проверка сайта на ПК и телефоне.

### Как менять стандарт
- Стандарт = этот раздел + общие файлы. Меняется **во всех репозиториях сайтов путешествий в один день**, одинаковыми PR.
- После правки общего файла: `node scripts/check-standard.mjs --update` (пересчитает `travel-standard.json`), затем тот же набор файлов и тот же `travel-standard.json` — в остальные репозитории. Без этого `npm run check` и CI упадут — так и задумано.
- Значимое изменение — новая версия в заголовке раздела (1.1 → 1.2) и строка в «Истории».

### Запрещено
- Менять общий файл только в одном репозитории; копировать в новый сайт старый «планировщик».
- Хранить личные данные в `localStorage` или в публичной сборке; публичная регистрация.
- Ключи и пароли в Git; root-доступ или произвольные команды из CI; выкладка мимо CI.
- Библиотеки с CDN; правка сгенерированных файлов; трогать на сервере настройки чужого сайта.

### Правила работы
- Изменения — через ветку и pull request; проверки PR зелёные до слияния.
- После выкладки: публичные разделы, вход, закрытые разделы, телефон 390 px без горизонтальной прокрутки.
- Тексты — на русском. В подвале: «made with ♥ by Roman A. Proskurnin».
